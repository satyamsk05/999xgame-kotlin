# Plan 08-01: Advanced Admin Analytics & Risk Scoring Implementation

**Phase:** 8 (Advanced Admin Analytics & Risk Scoring)
**Plan:** 08-01
**Mode:** tracer-first

## Goal
Implement `RiskScoringService`, automated `RISK_LOCKED` withdrawal state logic, platform analytics endpoints (`GET /api/admin/analytics/summary`), and risk override admin controllers.

## Requirements Addressed
- **RISK-01**: User Risk Scoring Service evaluating deposit velocity, withdrawal frequency, and multi-account signals.
- **RISK-02**: Automated risk-flagged withdrawal locking (`RISK_LOCKED`).
- **ANALYTICS-01**: `/api/admin/analytics/summary` REST endpoints for GGR, NGR, DAU, and deposit volume.
- **ANALYTICS-02**: Risk Management Admin Controller for user risk score overrides, manual user bans, and audit trail logging.

## Tasks

### Task 1: Risk Scoring Service & Automated Lock
- **Files**:
  - `backend/src/main/kotlin/com/ingames/admin/RiskScoringService.kt`
  - `backend/src/main/kotlin/com/ingames/wallet/FinancialService.kt`
- **Action**: Implement `RiskScoringService.evaluateUserRisk(userId)` calculating risk scores and tiers (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`). Update `FinancialService.requestWithdrawal` to auto-flag `RISK_LOCKED` for risk score >= 80.
- **Verification**: Unit test asserting high-risk users are assigned `RISK_LOCKED` withdrawal status.

### Task 2: Platform Analytics & Risk Overrides (`AdminAnalyticsService.kt`, `AdminRoutes.kt`)
